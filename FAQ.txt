# 📄 FAQ – Dead Entry Cleaner (BETA)

### ❓ What does this script do?

It removes **ghost entries** from Aurora (items that still appear in the library but no longer exist on the storage device).

👉 **Important:**

* It does **NOT** delete games.
* It does **NOT** remove DLCs.
* It does **NOT** modify Title Updates.

---

### ❓ Will this script delete my games?

❌ No.

It only cleans Aurora's **ContentItems database**.
Your game files remain completely untouched.

---

### ❓ What are "ghost entries"?

These are games or content that still appear in Aurora even though:

* The folder has been deleted.
* The `.xex` file no longer exists.
* The game was moved to another location.
* The content is incomplete or corrupted.

---

### ❓ Should I create a backup first?

⚠️ Recommended, but not required.

Common database locations:

```text
Data\Databases\content.db
User\Data\Databases\content.db
```

---

### ❓ Why are some entries not removed?

The script includes an **advanced protection system** and intentionally does **NOT** remove:

* Aurora
* XexMenu
* DashLaunch
* Emulators
* Essential homebrew applications
* Plugins, stealth services, and system utilities
* Multi-disc games
* Valid content

👉 This behavior is intentional to help protect your system.

---

### ❓ Can the script remove something important?

🛡️ Extremely unlikely.

It only removes entries that are safely identified as invalid, for example:

* Missing directory
* Missing XEX executable
* Invalid GOD package
* Empty directory

---

### ❓ What does each removal reason mean?

Examples include:

* `EMPTY_DIRECTORY` → Entry has no valid path.
* `DIRECTORY_NOT_FOUND` → The folder no longer exists.
* `XEX_NOT_FOUND` → Game executable is missing.
* `INVALID_GOD` → Corrupted or incomplete GOD package.
* `FALLBACK_GHOST_ENTRY` → Entry has no valid content.

---

### ❓ Why does it ignore some broken games?

This may happen if:

* The folder still contains some files.
* The game is a multi-disc title.
* The entry is protected by internal safety rules.
* The Title ID is invalid or considered suspicious.

👉 The priority is **safety**, not removing everything indiscriminately.

---

### ❓ Do I need to rescan afterward?

⚠️ It depends on your Aurora configuration.

👉 The recommended approach is to **enable automatic scanning** in Aurora.
After cleaning and restarting, Aurora will rebuild the library automatically.

If automatic scanning is disabled:

* Perform a manual scan afterward.

---

### ❓ Do I need to restart Aurora?

✔️ Yes (recommended).

👉 The script will prompt you to restart when it finishes.

---

### ❓ Does it work with both HDD and USB devices?

✅ Yes.

👉 Storage selection exists due to Aurora's database organization and path handling.
In practice, the cleaning process works across the selected database.

---

### ❓ Does it clean broken DLCs or Title Updates?

❌ Not directly.

The script does **not** modify:

* DLCs
* Title Updates

However, it may remove invalid database entries related to them.

---

### ❓ Does the script modify physical files?

❌ No.

It only executes:

```sql
DELETE FROM ContentItems
```

👉 In other words, it only removes entries from Aurora's database.

---

### ❓ Can errors occur?

They can, but they're uncommon.

Examples include:

* Database read failure
* Failed entry removal

👉 These are counted as failures in the report and do not damage the system.

---

### ❓ Can I run it multiple times?

⚠️ Yes, but keep this in mind:

* Running it again **without restarting Aurora** will likely find nothing.
* After restarting, if automatic scanning is enabled, Aurora may rebuild the library and new invalid entries may be detected.

👉 This behavior is normal and depends on how Aurora scans your content.

---

### ❓ Does this script replace Aurora's rescan feature?

❌ No.

It cleans the database, but rebuilding the library still depends on Aurora's scanning process.

👉 Recommended workflow:

* Run the script.
* Restart Aurora.
* Let Aurora's automatic scan rebuild the library.

---

### ❓ When should I use this script?

Use it when:

* Games appear but won't launch.
* Your library contains broken entries.
* You see duplicate or ghost entries.
* You manually moved or deleted games.

---

### ❓ Does it work on a stock Xbox 360 (without modifications)?

❌ No.

This script is designed for systems running:

* RGH
* JTAG
* Other compatible exploits
* Aurora Dashboard

---

## 💡 Extra Tip

If Aurora's game library frequently becomes cluttered with broken or ghost entries, this script resolves **most cases without requiring a full database reset**.
